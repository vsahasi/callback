**Overrules: none.** No majority breaks a hard rule or contradicts another majority. Two cases came close:
- **C3: name in the query string.** A query string can land in access logs, and the logs must carry no caller words. The fix is a logging duty, not a wire change:
  - the detector's `make run` gets `--no-access-log`;
  - the observability layer logs route templates only;
  - a log-hygiene test proves no name appears.
- **C17: disclosure order on the callback leg.** The disclosure is still the first line the callee hears, so the rule "a disclosure opens every call" holds. This only matters once a real listener exists, and the listener is not in Round 2. It is listed as an open item in §6.

**Consistency fixes**, needed so the majorities build together:
1. **F1. Voice fails.** One voice-fail rule serves mock and real mode. A passive voiceprint below 0.45 counts once. Each challenge that fails on the speaker counts once. Two voice fails deny. This produces J1's "the mock denies on the first failed challenge" for `human_impostor` without a separate mock-only rule.
2. **F2. Tier 2 voice freshness** combines J1's "after the latest `/caller`", J2 and J3's "≤ 60 s and bound to the params", and J1's "a `phrase` challenge". J2's 60 s rule alone could skip Call 1's second challenge after a fast callback.
3. **F3. Real mode with no text signal.** Tier 2 can never `allow`. It returns `step_up` with the missing factors, or `step_up ["voice_challenge"]` when nothing is missing. This keeps J1 and J2's fallback and the unanimous "a `step_up` is never empty". Veer's six-round cap then denies.
4. **F4. Jitter.** Mock jitter (150-400 ms, unanimous) applies to every `/v1` route except `/turns`, `/events` and the challenge poll. Background turn posts must not delay challenge resolution or eat the 1.0 s poll budget.
5. **F5. Acceptance is split by environment.** Eric's 3.11 suite replays the pinned HTTP sequence with raw `httpx`. Veer's 3.13 suite drives his real `Gate` and `DetectorClient` against a running detector. J1 had Eric's tests import Veer's client, which cannot run on 3.11.
6. **F6. The contract file is edited once, in a shared base commit, before the two agents start.** That base also carries PR 3. File ownership is split so the two branches never touch the same file.
7. **F7. Constants added to the shared file.** `MOCK_OTP_CODE`, `AUTHORIZE_SERVER_DEADLINE_S`, `DenyReason` and `ErrorCode` go in as constants, so both sides import the same strings. They are not referenced by any model, so the schema only gains the two error models.
8. **F8. Ended sessions** answer 409 `session_ended`, by majority. A locked session refuses new challenges, OTPs and enrollments with 409 `session_locked` (J1, unopposed; it follows from "deny is sticky").
9. **F9. `agent_say`** is always `""` on `/v1`. The agent ignores it, and an empty string can never leak a challenge phrase.
10. **F10. Mock values the judges split on** (display only): `cloned_voice` agent 0.10, `replay` agent 0.10, `ai_agent` text 0.40, `human_impostor` agent 0.05. Each keeps every script's outcome exactly as Notion's table.

## 2. The settled contract (callback_shared 1.1.0)

### 2.1 The artifact, its owner and its version

- **File:** `shared/src/callback_shared/contract.py`.
- **Distribution and import:** distribution `callback-shared` (`shared/pyproject.toml`). Both sides use `from callback_shared.contract import ...`.
- **Agent install:** already in place: `[tool.uv.sources] callback-shared = { path = "../shared", editable = true }` in `agent/pyproject.toml`.
- **Detector install:** `[tool.uv.sources] callback-shared = { path = "shared", editable = true }` in the root `pyproject.toml`, plus `callback-shared` in `dependencies`. The Modal image adds the `callback_shared` source.
- **Version:** `CONTRACT_VERSION = "1.1.0"`, and `shared/pyproject.toml` `version = "1.1.0"`.
- **Snapshot:** `shared/tests/snapshots/contract_schema.json`. It is regenerated exactly once, in the base commit (task V1), with:

  ```
  cd shared && uv run python -m callback_shared.contract --write-schema tests/snapshots/contract_schema.json
  ```

  After that it gains 2 models (30 in total) and `"version": "1.1.0"`.
- **Who edits it:** Veer's side, once, in task V1. Eric's side only imports it. Nobody edits it again before Round 2 is submitted. An agent that thinks a change is needed stops, and writes the need in its PR description for Veer and Eric.
- **The file must keep importing on Python 3.11.** No PEP 695 syntax.
- **Eric's `shared/contract.py`** stays at `0.1.0-provisional`, with `schemas/contract.schema.json` byte-identical. It is the internal model of the root `/events` API and of PR 3. It is not part of this contract.

### 2.2 Base URL and transport

- `DETECTOR_URL` is a scheme plus a host, with no path and no trailing slash. Examples: `https://<workspace>--callback-detector-fastapi-app.modal.run`, `http://127.0.0.1:8000`.
- Every contract route starts with `/v1`. All bodies are `application/json`. All times are integer Unix epoch milliseconds.
- A route that returns a body answers 200. A route without a body answers 204. The agent treats any 2xx as success and any non-2xx as failure.
- Outside the contract, and never called by the agent: `GET /healthz` (no auth), `POST /events`, `GET /factors/{session_id}`, `/review`, `/metrics`, PR 3's `POST /enrol/voice`, `/enrol/voice/status` and `/enrol/voice/erase`, and `POST /verify/bank-details`, which is unmounted unless `CALLBACK_BANK_VERIFY_ENABLED=1`.

### 2.3 Headers

| Header | Direction | Where | Rule |
| --- | --- | --- | --- |
| `Authorization: Bearer <token>` | agent → detector | every `/v1` request | Missing or wrong gets 401 `unauthorized`. The agent reads `DETECTOR_TOKEN`. The detector reads `DETECTOR_TOKEN`, falling back to `CALLBACK_API_TOKEN`, and refuses to start if both are set and differ. Auth is checked before the version header. |
| `X-Contract-Version: 1.1.0` | agent → detector | every `/v1` request | Missing, or a major version other than `1`, gets 400 `contract_version_mismatch`. A different minor or patch version is served, and the detector logs one warning per version string. |
| `X-Contract-Version: 1.1.0` | detector → agent | every `/v1` response, errors included | Informational. The agent does not read it. |
| `X-Callback-Scenario: real_cfo \| cloned_voice \| replay \| ai_agent \| human_impostor` | agent → detector | `POST /v1/sessions` only | **Mock mode:** pins the script for the life of the session. If it is absent, `real_cfo`. An unknown value gets 400 `invalid_scenario`. A repeat create for the same live session ignores it. **Real mode:** ignored, with one warning. Every other route ignores it in both modes. `claimed_user_id` never selects a scenario. |
| Idempotency | — | — | No header and no sequence numbers. The only key is `AuthorizeRequest.idempotency_key` (§2.10). |

### 2.6 Session rules

- **Session id:** `session_id` = `"ses_"` + 32 lowercase hex characters, minted by the detector.
- **Create** checks that `claimed_user_id` is in `users_on_file` (404 `user_not_found` otherwise). The claim is fixed for the life of the session. `/caller` changes only `caller_identity` and `channel`, and records `caller_changed_at`.
- **Create is idempotent per live room.** The same `room`, `claimed_user_id` and `caller_identity` return the existing id (200). The same room with any of those different gets 409 `session_conflict`. A room whose session has ended gets a new session.
- **At most 5 live sessions.** The 6th create gets 503 `too_many_sessions`.
- **A session ends on `/end`, 30 min after create, or 10 min after the last `/v1` call on it.** Expiry is checked on every access. An ended session answers 409 `session_ended` (except `/end`). It is evicted 60 min after it ends, and after that it answers 404.
- **A decision never ends a session.** The first deny locks it to tier 0 (§2.10). The caller leaving the room never ends a session.
- **Turns** are held in memory only, at most 200 per session. They are deduplicated on `sha1(f"{role}|{start_ms}|{end_ms}|{text}")`. The detector records the receive time of every user turn.
- **`/end` drops** turns, events, challenge `say` text and expected answers. It keeps decisions, numeric signals and reason codes until eviction.
- **One process holds the state, in memory.** The Modal function stays at `min_containers=1, max_containers=1`, which it already is.

### 2.7 Challenges

- **`challenge_id`:** `"chl_"` + 16 hex. **`expires_at`:** issue time + 45 000 ms.
- **`say` formats:**
  - `digits`: `"4 7 2, 9 1 3"` (6 random digits).
  - `phrase`: `"4 7 2, 9 1 3, amber, pillow, rocket"` (6 random digits plus 3 words from a curated list). The list has at least 64 two-syllable concrete nouns and colours, with no digit homophones, no proper nouns, and no pairs one edit apart (N:596).
  - `liveness`: behaves as `digits`.
  - `enroll`: the next prompt of the session's open enrollment, as a full sentence, because the agent speaks `say` with no lead-in. Prompts 1-3: `"Please repeat after me: 4 7 2, 9 1 3."` Prompts 4-6: `"Please repeat after me: amber, pillow, rocket."` Prompt 7: a free-answer question, such as `"In a sentence or two, tell me what you had for breakfast today."` A failed try reissues the same prompt number as a new challenge.
- **One pending challenge per session.** A create while one is pending supersedes it: the old one becomes `expired`, reason `superseded`.
- **Binding:** a `digits` or `phrase` challenge is stamped with the session's current `pending_bind` key (§2.10).
- **Mock resolution** is computed lazily on read from timestamps, using the registry clock. The challenge stays `pending` until the first `role=user` turn *received* after it was issued. It turns into the scripted result 700 ms after that receive time. If no user turn arrives before `expires_at`, it becomes `expired`, reason `no_answer`.
- **Real mode until the listener exists:** the same timing, but the result is `failed`, reason `no_audio`. With a listener, the word check (N:599-605) and the speaker score both have to pass.
- **Refused challenges:** a challenge counts as refused when it ended `expired` (with reason `no_answer` or `superseded`) without any user turn after it was issued.
- The detector never logs `say`.

### 2.8 OTP, Twilio and the code

- **The detector owns sending and checking.** The agent never sees a phone number for the code and never sees a generated code. It relays only the digits the caller speaks, to `/otp/check`.
- **Mock mode (default):** nothing is sent. `/otp/check` is `secrets.compare_digest(code, MOCK_OTP_CODE)`. If `CALLBACK_MOCK_SMS=twilio` is set and the Twilio variables are present, mock mode sends and checks through Twilio Verify instead. That is optional, for the recording.
- **Real mode:** Twilio Verify v2, called over `httpx` with basic auth and a 4.0 s timeout:
  - send: `POST https://verify.twilio.com/v2/Services/{TWILIO_VERIFY_SERVICE_SID}/Verifications` with form `To=<phone_e164>&Channel=sms`;
  - check: `POST https://verify.twilio.com/v2/Services/{TWILIO_VERIFY_SERVICE_SID}/VerificationCheck` with form `To=<phone_e164>&Code=<code>`. JSON `status == "approved"` means verified. A 404 means not verified. Any other failure is 502 `sms_failed`.
  - If the Twilio variables are unset in real mode, `/otp/send` and `/otp/check` answer 503 `otp_unavailable`.
  - Twilio generates the code. The detector never generates, stores or logs it.
- **Secrets**, in the detector's Modal secret `callback-detector` only: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE_SID`. Veer creates the account (D8) with code length 6 (the Verify default) and verifies Eric's phone on the trial.
- **Limits, per session:**
  - 1 send per 30 s and 3 sends in total. Past either, 429 `otp_rate_limited`.
  - 5 checks. The 6th check gets 429 `otp_rate_limited`.
  - A check before any send gets 409 `otp_not_sent`.
  - Each wrong code is 200 `verified: false` and counts as a failed check. Three failed checks make the next tier 1-2 authorize deny with `otp_failed`.
- **`Signals.otp`:**
  - `n/a` before any send;
  - `pending` after a send;
  - `verified` once a check passes;
  - `failed` after 3 failed checks.
- **The agent owns the spoken flow:** the prompt with the last two digits of `sent_to_last_four`, the parse, and three tries.

### 2.9 The number on file

- **Source:** the detector's `users_on_file`. `USERS_ON_FILE_JSON` (the JSON inline, which is how the Modal secret supplies it) wins over `USERS_ON_FILE_PATH` (a file path). With neither set, the directory is empty and the detector prints a loud warning. An invalid file stops the process at startup.
- **Schema:**

  ```json
  {"users": [{"user_id": "u_eric", "display_name": "Eric Catalano", "aliases": [], "role": "CFO", "phone_e164": "+15555550100"}]}
  ```

  - `phone_e164` must match `^\+[1-9]\d{7,14}$`, and `user_id` must be unique.
  - `phone_last_four` is `phone_e164[-4:]`.
  - The example above is committed as `users_on_file.example.json`, with a fictional 555-01xx number. The real `users_on_file.json`, holding Eric's real number, is gitignored and lives only in the Modal secret.
- **Name search:** both the query and each `display_name` or alias are normalized: strip, strip leading and trailing `.,!?`, casefold, collapse inner whitespace. A match is exact equality after normalization. Results come back in file order. The agent proceeds only on exactly one match.
- **Who uses the number:**
  - OTPs go only to the claimed user's `phone_e164`, inside the detector.
  - The agent gets `phone_e164` only from `GET /v1/users/{claimed_user_id}`, only to dial the callback, and it rejects an answer for any other `user_id`.
  - Neither side ever uses a number the caller says.
  - The full number appears in no log, session record, decision or journal, on either side. Logs carry at most the last four digits.

### 2.10 Authorize: vocabulary, factors and rules

- **Decision vocabulary:** `allow`, `step_up`, `deny`. Nothing else crosses the wire.
- **Step-up factors:** `voice_challenge`, `sms_otp`, `callback_on_file`, always listed in that order. `probe` exists but is never requested in Round 2. A `step_up` always lists at least one factor.
- **Bands (N:730-735):**

  | Signal | Bands |
  | --- | --- |
  | Voiceprint | pass ≥ 0.62 (the threshold reported in signals), fail < 0.45, grey between |
  | Spoof | low < 0.2, mid from 0.2 to below 0.6, high ≥ 0.6 |
  | Text | low < 0.3, high ≥ 0.7. `null` counts as not low. |
  | Agent likelihood | `null` counts as 0. It can only add a step-up and never denies on its own. |

- **Binding key:** `key = sha256(json.dumps({"action": action, "params": params}, sort_keys=True, separators=(",", ":")))`. The same key fingerprints the idempotency cache.
- **`pending_bind`:** when a tier 2 `step_up` includes `voice_challenge`, the session records `pending_bind = key`. A tier 1 `step_up` sets `pending_bind = None`.
- **Voice fail:** the passive voiceprint below 0.45 counts once per session. Each challenge that ended `failed` with `phrase_match` true (a speaker failure) counts once. A `no_audio` failure does not count.
- **Rules, first match wins:**
  1. **Tier 0:** `allow`, `ttl_s=0`, `reasons=["tier0_hold"]`. This holds even on a locked session.
  2. **Locked session:** `deny`, `reasons = ["session_locked", <locking code>, ...score lines]`.
  3. **Deny conditions**, checked in this order. The first that holds gives `reasons[0]`, and the session locks with that code:
     1. Real mode and the listener is not listening: `no_audio`.
     2. Spoof ≥ 0.6: `automated_caller` if agent ≥ 0.75, otherwise `synthetic_speech`.
     3. Any challenge in the session failed with `phrase_match` false: `challenge_failed_replay`.
     4. Two or more voice fails: `speaker_mismatch`.
     5. Three or more failed OTP checks: `otp_failed`.
     6. The latest callback report is `denied`: `callback_denied`. If it is `no_answer`: `callback_no_answer`.
     7. Two or more refused challenges: `challenges_refused`.
  4. **Tier 1 allow:** a `digits` or `phrase` pass resolved ≤ 300 s ago and after the latest `/caller` (consumed or not), spoof < 0.2, and agent < 0.75. Answer `allow`, `ttl_s=300`.
  5. **Tier 1 otherwise:** `step_up ["voice_challenge"]`, `ttl_s=120`.
  6. **Tier 2 allow** needs all of the following. Answer `allow`, `ttl_s=60`, and mark that pass consumed.
     - a `phrase` pass resolved ≤ 60 s ago, after the latest `/caller`, bound to this request's key, and not yet consumed;
     - spoof < 0.2;
     - OTP verified in this session;
     - text < 0.3;
     - the latest callback report is `confirmed`;
     - agent < 0.4.
  7. **Tier 2 otherwise:** `step_up` with the missing factors, in order, and `ttl_s=120`:
     - `voice_challenge`, if rule 6's voice clause fails or agent ≥ 0.4;
     - `sms_otp`, if no check has passed;
     - `callback_on_file`, if there is no confirmed callback.

     If that list is empty (spoof mid, or text not low), answer `step_up ["voice_challenge"]`.
- **Decision fields:**
  - `session_id` and `action` echo the request. Veer denies on any mismatch.
  - `risk_score = max(spoof, 1 − voiceprint, text, 0.8 × agent)`, skipping nulls. It is for display only.
  - `ttl_s` is 300 for a tier 1 allow, 60 for a tier 2 allow, 120 for a `step_up`, and 0 for a deny or a tier 0 allow.
  - `agent_say` is always `""`.
  - `signals`: `voiceprint` holds the passive score, threshold 0.62, `passed = score ≥ 0.62`, and the latest resolved challenge's `phrase_match`. `deepfake` holds the current spoof and `windows=8` in mock. `text` holds the risk, plus flags with `evidence=""`. `agent_likelihood` and `otp` follow §2.8.
  - `context` is accepted and ignored in Round 2, and never logged.
- **Score lines**, with 2 decimals. Deny reasons are `[code, *lines]`. Allow and step_up reasons are `[*lines]`.
  - `phrase_match false` (only for `challenge_failed_replay`);
  - `voiceprint_pass 0.83≥0.62` | `voiceprint_grey 0.50` | `voiceprint_fail 0.29<0.45`;
  - `spoof_low 0.04` | `spoof_mid 0.45` | `spoof_high 0.92`;
  - `text_low 0.10` | `text_mid 0.40` | `text_high 0.80`;
  - `text_flags: urgency, verification_refusal`, when there are flags;
  - `agent_likelihood 0.90`, when the agent score is ≥ 0.4.

  No reason, flag or field may carry caller words, challenge phrases, codes, or full phone or bank numbers.
- **Idempotency:**
  - The cache is keyed by `(session_id, idempotency_key)`.
  - The same key with the same fingerprint returns the cached Decision, with no jitter.
  - The same key with a different fingerprint gets 409 `idempotency_conflict`.
- **Deadline:** authorize answers within `AUTHORIZE_SERVER_DEADLINE_S` (2.2 s), measured from receipt with jitter included. A timeout or any internal exception answers 200 `deny`, `reasons[0]="internal_timeout"`, and that deny locks the session.
- **Real-mode signal mapping** (stretch):
  - voiceprint = `voice_match`, or P3's score for `"{user_id}:{channel}"`;
  - `spoof = 1 − synthetic_speech`;
  - `agent = 1 − agent_behaviour`, or `null` when there are no inputs.

### 2.14 The audio path, end to end

1. The caller reaches the LiveKit room by phone (SIP) or browser (WebRTC). The agent says the recording disclosure first, then identifies the caller, then calls `POST /v1/sessions`.
2. The agent sends the caller's audio only to Deepgram for STT. It keeps `record=False` and noise cancellation off. **No audio crosses the `/v1` wire.** Turns carry redacted text and epoch-ms word times.
3. **Mock mode:** no LiveKit join and no audio. Signals are scripted.
4. **Real mode, Round 2:** no listener, so tiers 1-2 are denied with `no_audio`, challenges fail with `no_audio`, and enrollment cannot complete. This is Notion's DEGRADED rule (N:388).
5. **Real mode with the listener** (stretch, needing no wire change):
   - On create, the detector joins as identity `detector-<session_id>` with `VideoGrants(room_join=True, room=<room>, hidden=True, can_publish=False, can_subscribe=True)` and `auto_subscribe=False`.
   - It subscribes only to the track of `caller_identity`, at 16 kHz mono int16, into a 90 s in-memory ring buffer anchored to epoch ms.
   - Windows feed `AnalysisEngine.analyse(samples, rate)`. Challenge clips feed P3's voiceprint.
   - `/caller` re-subscribes to the callee. `/end` leaves the room and drops the buffer.
   - Nothing is written to disk or to a bucket.
6. Eric's `AudioRef` path on `/events` is his offline harness only. `CALLBACK_AUDIO_ALLOWED_HOSTS` stays empty.

### 2.15 Enrollment and consent

1. The caller is identified (a session exists).
2. The agent runs `otp/send` and `otp/check` until verified (V4). The detector enforces this too: without a verified OTP in that session, enrollment gets 409 `otp_not_verified`.
3. The agent reads the N:854 consent text (`prompts.CONSENT_VERSION = "2026-11-04"`) and takes a plain yes.
4. `POST /v1/enrollments` with `Consent{version, verbatim, ts_ms}`. `user_id` must equal the session's claim, and `channel` the session's channel (409 `claim_mismatch` otherwise). The answer is `enrollment_id` = `"enr_"` + 32 hex, with `prompts_required` 7. A new start replaces any open enrollment on that session.
5. The detector appends `{consent_id, user_id, channel, version, verbatim, ts_ms}` to an append-only in-memory consent log. That log is a record, never an application log line.
6. The agent runs seven `enroll` challenges, each with up to 2 retries. It aborts after more than 2 prompts fail, and then never calls `complete`.
7. `POST /v1/enrollments/{id}/complete` answers `enrolled` when at least 5 of the 7 prompts passed, otherwise `failed`.

Further rules:
- Each channel enrolls separately. Real-mode prints go into P3's `VoicePrintStore` under the identity `"{user_id}:{channel}"`. They are prints, never audio.
- `DELETE /v1/enrollments/{user_id}` deletes `"{user_id}:phone"` and `"{user_id}:browser"`, and appends a `revoke` row.
- Mock mode always enrolls and writes no print.
- PR 3's `/enrol/voice*` routes merge unchanged as operator tools outside the contract. They must not enroll a real person until they also require a consent record, which is post-Round 2 work.

### 2.16 Redaction and logging duties

- **Agent: turn redaction**, applied to every `Turn`, of either role, before `Forwarder.submit`, in both `text` and `words[].w`:
  - **Digit tokens:**
    - a numeral run `[0-9]+`, which counts its length;
    - `zero` to `nine`, which count 1;
    - `oh` or `o`, only next to a digit token, which count 1;
    - `twenty` to `ninety`, which count 2 with or without a following unit word (`forty two` is 2 digits);
    - `double X`, which counts 2, and `triple X`, which counts 3.

    Use `spoken.py`'s vocabulary and its rules.
  - **A run** is a maximal sequence of digit tokens separated only by whitespace, `-`, `,` or `.`. In `words`, it is consecutive entries whose `w`, with trailing `,.-` stripped, are digit tokens.
  - **Rules:**
    - A run of 7 or more digits always becomes `[NUM]`.
    - A run of 4 to 6 digits becomes `[NUM]`, unless it is in the user turn that answers a `secret=True` ask, meaning a voice challenge or an enroll prompt.
    - Runs of 1 to 3 digits pass.
    - Agent turns get no exemption.
  - **Replacement:** in `text`, the run becomes the single token `[NUM]`. In `words`, the run's entries collapse into one `Word(w="[NUM]", start_ms=first.start_ms, end_ms=last.end_ms)`.
  - The OTP answer is not a secret ask, so it is redacted. The code reaches the detector only through `/otp/check`.
- **Agent: other duties.**
  - Authorize params carry the last four digits and a fingerprint (unchanged).
  - Logs carry no turn text, phrases, codes or full numbers (unchanged).
- **Detector: never logs or journals** turn `text` or `words`, `say`, `code`, `phone_e164`, the `name` query or the query string, `consent.verbatim`, `context`, raw `room` or raw `caller_identity`.
  - `room` and `caller_identity` appear in logs only as `hmac_sha256(per_process_key, value)[:16]`.
  - The observability request allowlist (`_EVENT_FIELDS`) gains no `/v1` fields.
  - `make run` passes `--no-access-log` to uvicorn.
